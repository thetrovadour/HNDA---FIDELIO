# M2 — IDOR Fix on `/api/users/:id`

**Date:** 2026-04-07  
**Time:** 20:20 CST  
**Status:** ✅ Fixed — 44/44 tests passing

---

## What was the vulnerability

**IDOR (Insecure Direct Object Reference)** on two user routes:

- `GET /api/users/:id`
- `GET /api/users/:id/transactions`

Once real user JWTs are issued (mainnet), a logged-in user could change the `:id` parameter in the URL to access another user's profile and transaction history. No ownership check existed — only admin access was gated.

---

## What was changed

### `packages/backend/src/middleware/auth.ts`

Added Express type augmentation:
```typescript
declare global {
  namespace Express {
    interface Request {
      admin?: jwt.JwtPayload | string;
      user?: { id: string; role: 'user' };
    }
  }
}
```

Added `userAuth` middleware — verifies user JWT, enforces `role: 'user'` payload:
```typescript
export function userAuth(req, res, next): void
```

Added `selfOrAdmin` middleware — the IDOR guard:
```typescript
export function selfOrAdmin(req, res, next): void
// Passes if: decoded.role === 'admin'
// Passes if: decoded.role === 'user' AND decoded.id === req.params.id
// Blocks with 403 otherwise
```

### `packages/backend/src/routes/users.ts`

Replaced `adminAuth` with `selfOrAdmin` on both affected routes:
```
GET /api/users/:id             → selfOrAdmin
GET /api/users/:id/transactions → selfOrAdmin
```

## Access matrix after fix

| Caller | Token | Can access `/users/123` | Can access `/users/456` |
|---|---|---|---|
| Admin | `role: admin` | ✅ | ✅ |
| User 123 | `role: user, id: 123` | ✅ | ❌ 403 |
| User 456 | `role: user, id: 456` | ❌ 403 | ✅ |
| No token | — | ❌ 401 | ❌ 401 |

---

## Why this matters

CATR balance and transaction history are financial data. An IDOR here would expose a client's full payment history to any other authenticated user. Fixed before mainnet.
